# Abacus — вимірювання витрат моделей (пілот)

Це **не** твердження про вже понесені витрати. Новий модуль `modules/telemetry/cost_telemetry.py` призначений для майбутніх **фактичних API-викликів**. Він не змінює cron, checkpoints, Gmail, Drive, Tasks, Calendar або існуючі брифінги.

## Контракт інтеграції

Після відповіді API передайте до `record_usage`: `run_id`, `task_id`, фактичні `provider/model`, `status`, вхідні та вихідні токени **з відповіді провайдера** й rate snapshot з відомим джерелом/датою. Шлях локального журналу задає інтеграція, наприклад `var/private/ai_usage.jsonl` (ігнорувати Git). Ніколи не записуйте prompts, тіло листа, медичні дані, API ключі.

Розцінки й usage не відомі → `null`, а не нуль. Оцінка в USD стосується тільки API, не ChatGPT Business/Tasks та не внутрішніх кредитів Abacus. Окремо від моделі фіксуйте run status/повноту процесу в існуючих receipts; успіх повідомлення не означає успіх задачі. `summarize` повертає total_cost_usd=null, якщо хоча б одна подія не має оцінки.

## Перший контрольований тест

1. Включити інструментування лише для реально знайдених клієнтів LLM; поточний `handoff` виконує більшість дій програмними правилами, тому не треба вигадувати model usage.
2. Виконати 30+20+15+10 контрольних задач із знеособленими fixtures; для критичних помилок поріг 0, економія на **успішну** задачу ≥30% проти baseline.
3. Порівняти кількість спроб, retries, latency, токени, ставки, помилки, незалежний readback.
4. Залишити production маршрут без змін, доки не пройдено перевірку.

Тести: `python -m unittest discover -s tests -p 'test_cost_telemetry.py'`.

Потрібен додатковий етап перед заявою про реальну економію: точна конфігурація billing/usage провайдера Abacus та фактичний перехоплювач його API-викликів. Не включати цей модуль у workflow до підтвердження його маршруту.
