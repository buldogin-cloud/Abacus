# Архітектура Command Center

> **Мета:** менше рутини — більше часу на стратегічні рішення та розвиток служби анестезіології.

**Command Center** — єдиний цифровий контур для управління інформацією,
обладнанням, документами та розвитком служби. Цей документ описує
екосистему автоматизації: джерела даних, агентів, проекти, бази знань і
результати для користувача.

---

## 🧱 Рівні екосистеми

### 1. Джерела даних (звідки надходить інформація)

| Джерело | Що дає |
|---------|--------|
| **Gmail** | листи, запити, документи |
| **Google Calendar** | події, зустрічі, нагадування |
| **Google Drive** | документи, папки, накази |
| **Офіційні джерела** | МОЗ, НСЗУ, закупівлі, стандарти |
| **Внутрішні звіти** | ВАІТ / БІТ, відділення |
| **Інші джерела** | постачальники, партнери, команда |

### 2. Автоматизації та агенти (що працює)

| Агент | Роль | Статус |
|-------|------|--------|
| **Command Center** | цифровий секретар: аналіз, контроль, нагадування | Працює (базово) |
| **Дослідник** | моніторинг МОЗ, НСЗУ, анестезіологія, AI, оснащення | Працює автономно |
| **Автоматизації** | скрипти, парсери, нагадування, звіти | Частково працює |
| **Інтеграція з Obsidian** | створення та звʼязування знань | Частково працює |

### 3. Проекти та процеси (що робиться)

| Проект | Опис | Статус |
|--------|------|--------|
| Управління завданнями | реєстр, контроль виконання, дедлайни | Працює |
| Оновлення протоколів | анестезіологія та реанімація | На стадії проекту |
| Облік обладнання | реєстр, несправність, заявки на ремонт, дефіцит | Частково працює |
| Моніторинг закупівель ВОКЛ | парсинг, звіти, можливості | На стадії проекту |
| Індексація папки «Робоча» | читання та структура документів | На стадії проекту |
| Second Brain (Obsidian) | база знань, звʼязки, розвиток ідей | Частково працює |
| Планування розвитку служби | цілі, KPI, стратегічні ініціативи | На стадії проекту |

### 4. Бази даних та знань (де зберігається)

| Сховище | Призначення |
|---------|-------------|
| **Google Sheets** | реєстр завдань, облік, звіти |
| **Google Drive** | документи, протоколи, накази, архів |
| **Obsidian** | база знань, повʼязані нотатки |
| **Спеціалізовані бази** | обладнання, закупівлі, дефіцит, ремонти |

### 5. Користувач та результати (для чого це)

- **Щоденний брифінг** — ключові події, задачі, ризики, наступні кроки.
- **Оперативне управління** — вирішення проблем, контроль виконання.
- **Стратегічні рішення** — розвиток служби, закупівлі, оснащення.
- **Економія часу** — менше рутини, більше фокусу.
- **Підвищення якості** — безпека пацієнтів, відповідність стандартам.

## 🔄 Потік даних щоденного брифінгу

```
Gmail ─────┐
Calendar ──┼──► briefing.py ──► briefing_YYYY-MM-DD.md ──► користувач
Sheets ────┤        ▲
Дослідник ─┘        │
                config.yaml
```

1. `briefing.py` завантажує `config.yaml`.
2. Ініціалізує клієнтів (`GmailClient`, `CalendarClient`) та `TaskManager`.
3. Збирає секції: пошта → календар → завдання → дайджест Дослідника.
4. Формує markdown і зберігає у `briefings/`.
5. За потреби надсилає брифінг поштою (Gmail API).
6. У CI (GitHub Actions) результат зберігається як артефакт.

## 🧩 Модульна структура коду

```
integrations/            # Низькорівневі клієнти Google API
  google_auth.py         #   спільна OAuth-автентифікація
  gmail_client.py        #   GmailClient
  calendar_client.py     #   CalendarClient
  sheets_client.py       #   SheetsClient

modules/                 # Прикладні модулі (бізнес-логіка)
  daily_briefing/        #   формування брифінгу
  task_manager/          #   TaskManager (реєстр завдань)
  researcher/            #   Researcher (моніторинг джерел)
```

**Принцип поділу:** `integrations/` відповідають лише за доступ до API,
`modules/` — за прикладну логіку. Це дозволяє повторно використовувати
клієнтів (напр. `SheetsClient`) у майбутніх проектах (облік обладнання,
моніторинг закупівель) без дублювання коду автентифікації.

## 🔐 Безпека та секрети

- Облікові дані (`credentials.json`, `token.json`), `config.yaml` та `.env`
  **ніколи** не потрапляють у git (див. `.gitignore`).
- У CI секрети передаються через **GitHub Actions Secrets**
  (`GOOGLE_CREDENTIALS`, `GOOGLE_TOKEN`, `CONFIG_YAML`).
- OAuth-області доступу мінімізовані до потрібних сервісів
  (Gmail, Calendar readonly, Sheets).

## 🗺️ Напрямки розвитку

1. Довести Command Center до повної автоматизації.
2. Запустити реєстр протоколів із контролем актуальності.
3. Завершити облік обладнання (заявки, ремонти, дефіцит).
4. Запустити моніторинг закупівель ВОКЛ.
5. Інтегрувати Дослідника з Obsidian (автоматичний імпорт).
6. Завершити індексацію папки «Робоча».
